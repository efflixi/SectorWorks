# SectorWorks v0.5.0-phase5 development prerelease

This prerelease covers the completed optical and BIN/CUE work through Phase 5,
file import by drag-and-drop and clipboard, and bounded compatibility fixes.
It is not 1.0. Phases 6 and 7 and the existing post-1.0 deferrals are unchanged.

## Compatibility pass

The read-only audit examined all 1,609 candidates. Of the 108 inputs in the 56
groups with one to four matches, 12 gained an edit path and three that previously
failed to open now open. The collection went from 240 to 252 editable inputs;
no previously available capability was lost. Two now qualify for disk editing
and ten for optical rebuild to a new image. The detailed report with owner paths
is kept locally as `Existing_File_Compatibility.md`, not included in the release.

- Recognized legacy ISO root records, timestamp variants, inline copyright
  labels and the mkisofs mastering sector without dropping their metadata.
- Opened case-mismatched CUE companions on Linux only when the adjacent match
  was unique and the existing no-link checks succeeded.
- Allowed bounded stale FAT32 backup hints while retaining the primary summary,
  allocation checks and boot/metadata preservation. Two additional examples
  still exceed the existing allocation-validation budget.

CloneCD sidecars, unqualified UltraISO metadata, unknown optical extents,
ambiguous hybrid layouts and unsupported NTFS states remain gated.

## Verification

- Linux x64: **2,481 passed, one skipped** across all five solution test
  assemblies. The skip is the Windows-only BCL security reference. The
  complete Services suite passed after correcting its stale expectations.
  The separate sparse-file regression, four Python harness suites, format,
  AppRun, UI-resource and reference-copy checks also passed.
- Windows 11 x64 laptop: **2,438 passed, 19 skipped, zero unresolved
  failures** across all five assemblies and the exact-case reruns. Eighteen
  skips require Linux optical authoring/oracles; one requires Linux XDG.
  The initial fixture-tool, export-setup, and sparse-file failures were
  retained, and all 33 affected test cases passed on recheck.
- Windows writer and storage tests ran on the laptop without UAC. QEMU image
  conversion used a verified portable executable; Linux-hosted NTFS and FAT
  oracles performed 4,948 successful fixture commands, including two setup
  controls, on the exact generated bytes. Another 294 independent checks
  verified all 21 mixed-volume Windows input/Save As/commit sets, including
  unchanged dirty siblings. These are not native Windows kernel authoring
  or elevated disk-attachment tests.

The Windows desktop used the packaged x64 executable at standard-user
privilege. It opened a generated ISO, added a file through the native picker,
and rebuilt to a new ISO. The rebuilt output was independently read on Linux;
both payloads matched and the Windows source SHA-256 stayed unchanged.
The packaged Linux AppImage also opened and closed in an isolated desktop.

Regression updates retain negative coverage for unsupported FAT metadata and
floppy geometry. Tests that expected supported FAT12/16 or MBR/GPT variants
to be read-only now exercise their qualified behavior. The Windows large-offset
test explicitly makes its own fixture sparse instead of trying to allocate 8 TiB.

## Packages and limits

Portable Linux x64 and ARM64 tarballs, Windows x64 and ARM64 ZIPs, a Linux x64
AppImage and SHA-256 checksums. No macOS build is produced. ARM64 packages are
cross-published only; physical ARM64 validation remains deferred. No elevated
Windows tests were attempted. Optical edits rebuild to new files only; neither
bootability nor exact physical-layout preservation is guaranteed.

## Cleanup

Removed 4.4 GB of reproducible project build output and stale default publish
staging. Earlier release packages, documentation, test source, fixtures,
qualification evidence, and owner images were retained.
